# Javada — Java шаг за шагом

Локальный тренажёр для одного ученика: подробная теория, переписывание кода, тесты, пропуски, сопоставление, задачи Парсона и **настоящая компиляция/запуск Java**. Интерфейс на русском; прогресс и черновики остаются в браузере **и** синхронизируются с локальным `.javada/progress.json` для плагина IntelliJ IDEA. Учётная запись и Node.js для запуска **не нужны**.

## Запуск

1. Установите **Python 3.10+** и **JDK 17+**. Проверьте в *том же терминале*, где будете запускать сервер:
   ```bash
   python --version
   javac -version
   java -version
   ```
2. Из корня репозитория перейдите в проект и выполните две команды:
   ```bash
   cd java-trainer
   pip install -r requirements.txt
   python server.py
   ```
   Браузер автоматически откроет **http://localhost:8000**. Если не открылся — перейдите по адресу вручную. Для остановки нажмите Ctrl+C.

На Debian/Ubuntu с ошибкой `externally-managed-environment` используйте виртуальное окружение вместо системного `pip`:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python server.py
```

На Windows активация обычно `.venv\Scripts\activate`, а запуск — `py server.py`. Если порт 8000 занят, задайте `TRAINER_PORT=8001` (в PowerShell: `$env:TRAINER_PORT="8001"`). Компиляция доступна только при локальном запуске без `TRAINER_HOST`.

### IntelliJ IDEA и общее сохранение

Исходники и инструкция по сборке **[плагина IDEA](idea-plugin/README.md)** лежат в `idea-plugin/`. Плагин **не запускает** Flask: сначала запустите `python server.py` самостоятельно, затем подключитесь к `127.0.0.1:8000` (или укажите другой локальный порт). В IDEA можно открыть и проверить все **44 прежние задачи с кодом**, 99 необязательных хардов и 5 лабораторий. Остальные уровни урока остаются в веб-интерфейсе. Для сборки плагина нужен JDK 17+, IDEA 2024.1+ и интернет при первой загрузке Gradle/SDK; для обычного запуска сайта сборка плагина не нужна.

Профиль находится в `java-trainer/.javada/progress.json` и создаётся сервером при первой записи. Старый `javada.state.v1` и черновики `javada.draft.v1.*` **не удаляются**: браузер импортирует их в профиль при подключении и затем периодически объединяет изменения IDE и браузера. Чтобы перенести старые данные, откройте браузер с **прежнего адреса** (`localhost` и `127.0.0.1` — разные хранилища браузера). После этого нажмите «Обновить» в IDEA. Награды за уже отмеченные задания не начисляются второй раз; хард даёт отдельное достижение. Профиль только на этом компьютере, не в облаке. Сброс в настройках сайта удаляет оба локальных сохранения; сделайте резервную копию перед сбросом при необходимости. При сетевом предпросмотре API профиля и компиляция недоступны.

## Как пользоваться

1. На карте выберите первый доступный модуль. Все 22 модуля уже наполнены; уроки открываются по порядку. После них доступна практика, а в модулях 17–22 сначала идёт стоп-урок из пяти вопросов (зачёт — 4/5), затем практика. Следующий модуль откроется после успешного стоп-урока (если он есть) **и** практики предыдущего.
2. В уроке читайте конспект и **второй разобранный пример**: зачем нужен приём, последовательность действий, конкретный код, результат и подсказку, как перенести идею на задание. Там, где указан «Полная программа Main.java», показан самостоятельный запускаемый файл и точный вывод строк; фрагменты SQL/Spring и кода для более крупного проекта подписаны отдельно. Уже в первом уроке показаны `public class Main`, метод `main`, объявления `age`/`name`, `System.out.println(age)`/`System.out.println(name)` и разница между `name` и `"name"`. При установленном JDK полный пример можно сохранить в `Main.java` и выполнить `javac Main.java`, затем `java Main`. Ошибка в мини-задании даёт подсказку, а попытки не ограничены.
3. **Перед практикой каждого модуля** прочитайте отдельную подготовку с пошаговым объяснением, полной аналогичной программой и её выводом. Для двух задач с кодом есть указания по подходу, но в самом задании используйте его собственные данные и условия. После первого задания подготовка остаётся слева; на узком экране к следующему заданию можно сразу перейти, не прокручивая объяснение снова.
4. В сопоставлении нажимайте пункт слева, затем подходящий справа. В задаче Парсона перетаскивайте строки **или** используйте кнопки ↑/↓; кнопки −/+ задают уровень отступа (число между ними). Проверяются **и порядок, и отступы**. Если порядок верен, но отступы нет, тренажёр подсветит строки и покажет нужные уровни; такую промежуточную попытку не запишет как ошибку. Все задания доступны с клавиатуры.
5. В задаче с кодом редактируйте `Main.java` (черновик сохраняется автоматически), нажмите «Запустить проверку». `javac` покажет подлинную ошибку компиляции, либо программа запустится с лимитом **5 секунд** и её вывод сравняется с ожидаемым. При сбое сервера или отсутствии JDK попытка не записывается как ошибка.
6. В каждом из 99 уроков сначала **перепишите пример вручную** (8 XP), затем пройдите уровни **лёгкий (10 XP)**, **средний (20 XP)** и **сложный (35 XP)**. Четвёртый уровень — **хард (90 XP)**: самостоятельная программа на тему урока, необязательная для прохождения, с достижением за успех. Его можно пропустить и позже открыть отдельно из списка уроков. Черновики переписывания и Java-кода сохраняются. Прежние задачи практики сохраняют свои ID и старую схему XP: теория 5, тест 10, пропуски 15, пары 20, Парсон 25, код 50. Со второго дня серии действует бонус +10%; на 7-й и 30-й дни — ещё 50/200 XP. Повторение приносит 5 XP за вопрос не чаще раза в день.
7. После окончания модуля вопросы, где были ошибки или которые не встречались 7 дней, появляются в разделе «Повторение». При открытии урока с вероятностью 30% один такой вопрос вставляется в текущую сессию (если уже завершён более ранний модуль).
8. Откройте **«К junior»** в меню (`#/career`): пройдите пять лабораторий с разными входами, затем скачайте заготовки проектов. Лаборатории доступны независимо от очередности модулей; рекомендуемые модули подписаны. За них не начисляется XP: цель — навыки, а не игровой балл. Черновики и отметки о пройденных проверках хранятся в браузере и общем локальном профиле. Чек-лист проектов заполняете сами — это не автоматическая оценка.

### Напоминания

Откройте **Настройки → Напоминания о занятиях**: выберите местное время и вручную включите переключатель. Только по нажатию тренажёр запросит разрешение на уведомления. Если браузер их поддерживает и разрешает, уведомление придёт **не чаще одного раза в день**, только когда вкладка с тренажёром открыта в это время (в пределах часа) и вы ещё не занимались сегодня. Отключить можно там же. Если устройство спит или браузер выгрузил вкладку, доставка не гарантируется даже при разрешении. На `localhost` и `127.0.0.1` современные браузеры обычно разрешают эту возможность; в изолированном предпросмотре или при запрете разрешения она может не работать. Приложение не обещает доставку после закрытия вкладки: у локального сервера нет push-сервиса.

Для напоминания **с закрытым тренажёром** скачайте `.ics` в том же разделе и **импортируйте** его в своё приложение календаря. В файле — ежедневное повторение и сигнал в выбранное время по часовому поясу календаря; дальнейшую доставку обеспечивает календарь и его настройки, не браузер и не сервер Javada. Скачивания без импорта недостаточно. Если время изменилось или вы сбросили данные тренажёра, старое событие в календаре нужно удалить вручную и при необходимости импортировать новое.

**Все 22 модуля готовы:** 99 уроков (по четыре в модулях 1–3), **679 заданий**, семь заданий практики на модуль и шесть типов взаимодействия, включая переписывание. Каждый урок содержит цель, основные абзацы, углубление (механизм и применение), короткий пример с разбором, **второй пошаговый пример с объяснением и результатом**, типичную ошибку, переписывание кода и четыре уровня (хард необязателен). Все 99 разборов написаны под конкретные темы; в каждом из 22 практикумов есть подготовка с полной аналогичной программой и точным выводом. Прежние два мини-задания в каждом уроке и 44 задачи практики с кодом сохранили свои ID и условия; добавлены 99 упражнений на переписывание, 99 задач «сложный» и 99 хардов с реальной компиляцией. Модули 17–22 дополнительно содержат стоп-урок с пятью вопросами и проходным баллом **4/5 (80%)**. Темы охватывают Java, ООП, коллекции, алгоритмы, многопоточность, паттерны, SQL, Spring, REST, тестирование и CI/CD. Это **ёмкий вводный курс**, а не замена самостоятельному проекту и углублённому изучению всех 22 тем.

## Практическая траектория: junior Java backend

| Этап | Что проверить самостоятельно | Встроенная практика |
| --- | --- | --- |
| Java Core, модули 1–9 | циклы, `long`, ООП, `Map`, обработка отсутствующих данных | минимум/максимум/сумма; каталог пользователей |
| Надёжность и данные, 10–16 | валидация ввода, исключения, агрегация/сортировка | импорт строк; агрегирование заказов |
| HTTP и backend, 17–22 | методы/пути/статусы; отдельно Spring, БД, тесты и CI | модель HTTP-маршрутизатора |

Каждая из **5 лабораторий** компилируется одним `javac` и запускается на **4 разных входах** в рамках общего лимита 5 секунд. Пример виден заранее, остальные 3 входа находятся в `private/lab_cases.json` на стороне локального сервера, а **не** в публичном JSON или запросе браузера. При ошибке выводится первый непройденный случай, чтобы можно было исправить программу. Файл с проверками в локальном репозитории доступен владельцу ноутбука: это помощь в обучении, **не защита от списывания и не изолированная песочница**. 44 прежние задачи с кодом и 99 новых хардов по-прежнему проверяют единственный ожидаемый вывод.

Из раздела можно скачать две самостоятельные заготовки ZIP (или открыть исходники в `projects/`):

- **Task Tracker CLI** (`projects/task-tracker/`): JDK 17+, Python 3.10+ для `verify.py`; реализуйте бизнес-правила, запись/чтение файла и свои тесты. Начальная заготовка намеренно не проходит проверку.
- **Task API** (`projects/task-api/`): реальный Spring Boot + JPA + H2, JUnit/MockMvc, Maven 3.9+ и интернет **для первого скачивания зависимостей**. Добавьте PATCH/DELETE, сервис/DTO, проверки и документацию. Один тест намеренно красный, пока не реализован PATCH. Проект запускается **отдельно** от Flask-тренажёра.

Критерий результата — вы можете написать и разобрать код на граничных случаях, запустить тесты, показать историю коммитов, объяснить HTTP-статусы/структуру приложения и ссылку на свой репозиторий. **XP, пять зелёных лабораторий или отмеченный чек-лист сами по себе не доказывают готовности к найму.** Для уверенного junior backend дополнительно нужны практика SQL на настоящей БД, код-ревью и самостоятельное решение новых задач.

**Ограничение локальной проверки:** для самого тренажёра нужны только Flask и JDK, но не Maven, Spring, JDBC-драйвер, БД, JUnit, Mockito, Docker или GitLab. Теория и тесты знакомят с ними, но встроенный компилятор на продвинутых темах *моделирует принципы на стандартном JDK*, а не запускает Spring-приложение, SQL-запрос, JUnit-тест или контейнер. Работа с настоящим Spring/БД вынесена в отдельную заготовку с внешними зависимостями.

## API и добавление контента

- `GET /api/health` — доступность компилятора.
- `GET /api/modules?completed=1,2&bossPassed=17` — метаданные и статусы (`available`, `locked`, `completed`); для этого конкретного ответа учитываются параметры из текущего браузера (копия прогресса также хранится в локальном профиле). Без параметров доступен первый модуль. Все 22 модуля сейчас имеют `contentStatus: "ready"`; статус `planned` зарезервирован для возможных новых модулей без контента.
- `GET /api/ide/tasks` — локальный каталог 44 прежних задач с кодом, 99 хардов и 5 лабораторий для плагина; приватные наборы лабораторий не передаются. `GET /api/progress` возвращает состояние и черновики из `.javada/progress.json`; `POST /api/progress/merge` объединяет браузерное сохранение; `POST /api/progress/draft` обновляет черновик; `POST /api/progress/reset` с `{ "confirm": true }` сбрасывает профиль. Эти маршруты доступны **только** при локальном запуске Flask.
- `GET /data/labs.json` — условия, начальный код и один пример каждой лаборатории; другие наборы ввода браузеру не передаются.
- `GET /api/projects/task-tracker/starter` и `/api/projects/task-api/starter` — ZIP заготовок с исходниками, README, тестами и CI. Имя проекта выбирается из фиксированного списка; каталог `private/` в архив не попадает.
- `POST /api/compile` — JSON `{ "code": "public class Main { ... }", "taskType": "run", "taskId": "lab-array-report" }` (или обычный ID задания, например `m01-p06`). Режим `run` возможен только для известного серверу ID; ответы/входы из запроса клиента игнорируются. Обычная задача сверяет stdout с `expectedOutput` из JSON курса; лаборатория сверяет каждый stdout с локальными `private/lab_cases.json` (4 входа). Игнорируются разница `CRLF`/`LF` и пробелы в конце строк, но не порядок строк или пробелы внутри результата. Команда `javac` выполняется раз, затем все запуски делят 5 секунд. Режим `compile` компилирует без запуска и допускает отсутствие `taskId`. Ответ `{ "success": true|false, "kind": "ok|compile_error|wrong_output|runtime_error|timeout|...", "output": "...", "error": "..." }`. Плагин добавляет `"recordProgress": true`: после успешного выполнения сервер атомарно записывает награду/достижение и возвращает `progress`; при ошибке начислений нет. Ошибки ученика — HTTP 200, ошибки сервера — 4xx/5xx.

Чтобы изменить контент **модулей 4–22**, редактируйте авторские спецификации `tools/modules_04_08.py`–`tools/modules_19_22.py`. Цели, разборы короткого примера и типичные ошибки **всех** уроков — в `tools/lesson_notes.py`; углублённые объяснения и сценарии — в `tools/lesson_extensions.py`. Вторые пошаговые примеры, их точный вывод и связь с упражнением редактируйте в `tools/guided_lessons.py` (99 записей); **сложные вопросы и харды** — в `tools/mastery_challenges.py` (по 99 записей); подготовки к практике и подсказки для p06/p07 — в `tools/practice_guides.py` (22 записи). Если `runnable=True`, добавьте точный вывод в `RUNNABLE_OUTPUTS`; неполный фрагмент явно подпишите контекстом, не обещая самостоятельный запуск. Затем из каталога `java-trainer` выполните `python tools/generate_course.py`: он обновит теорию, добавит новые задания в модулях 1–3 **с сохранением прежних ID q1/q2**, и полностью пересоберёт модули 4–22. Потребуется лишь Python 3.10+; генерация **не нужна для обычного запуска**. Заголовки и количество уроков берутся из `frontend/data/modules.json`, а основные задания модулей 1–3 редактируются прямо в их JSON. После изменений запустите тесты.

Для новой лаборатории добавьте публичное описание в `frontend/data/labs.json` (уникальный `lab-*`, `type: code`, `mode: run`, пример, `starterCode`) и **отдельно** четыре входа/ответа в `private/lab_cases.json`; первый должен совпасть с примером. Обновите тесты и учитывайте общий лимит исполнения 5 секунд. Обе JSON-части загружаются сервером при первом обращении, поэтому после правок перезапустите Flask и сбросьте часовой кэш браузера `javada.cache.v8.labs`.

Для новых упражнений используйте типы `copy` (`sourceCode`, `language`), `choice` (`options`, `correct`, `multiple`), `fill` (`template`, `blanks`), `matching` (`pairs`), `parsons` (`lines`, `solution` с отступами 0–3), `code` (`starterCode`, `mode: "run"`, `expectedOutput`). Пропуск по умолчанию проверяет точное совпадение с `answer`; для конечного набора синонимов укажите `accepted: ["вариант1", "вариант2"]`, а если по условию допустим диапазон чисел — `validation: {"kind": "integerRange", "min": 0, "max": 120}`. Любые варианты должны быть явно отражены в условии. В `parsons` укажите только действительно равнозначные перестановки в `alternativeOrders` (массивы ID строк); отступ привязан к строке из `solution`, одинаковые закрывающие скобки взаимозаменяемы. В Python-источнике это аргумент `alternative_orders` у `P(...)`. Остальные перестановки, меняющие смысл программы, остаются ошибками. Например, в задаче про возраст принимаются и `int age = 3;`, и `int age = 25;` — пример из теории не единственный ответ. У задания обязательны уникальный `id`, `prompt`, `hint`, `explanation`. Код пишется в **публичном классе Main** без `package`; ожидаемый вывод хранится в JSON курса на сервере, а не принимается из запроса клиента. Для стоп-урока нужны пять вопросов, `boss` в `modules.json` и порог 0.8.

Метаданные и уроки кэшируются в браузере на час. Ключи кэша `javada.cache.v8.*` отделены от прогресса и черновиков `javada.state.v1` / `javada.draft.v1.*`: обновление курса сохраняет уже заработанные XP, прохождения, историю ответов и код. При загрузке старого сохранения ненужные поля жизней, таймера восстановления и компенсаций отбрасываются; пройденные уроки и модули не сбрасываются. Настройки браузерных напоминаний сохраняются рядом с прогрессом, но импортированное в календарь событие удаляется вручную. При отладке содержимого удаляйте **только кэш**, не `javada.state.v1`; после изменения источников перезапустите сервер (он кэширует индекс в памяти). Не удаляйте `.javada/progress.json` ради обновления курса: это общая копия прогресса и черновиков IDEA. Старый профиль из браузера переносится только после открытия старого origin.

Интерфейс меняется через CSS-переменные в `css/main.css`, в том числе `--green`, `--yellow`, `--red`, `--bg`, `--text`. Тёмная тема уже есть в настройках. Правила XP и повторения находятся в `js/utils/constants.js`, логика — в `gamification.js` и `review.js`. Новые типы заданий добавляйте в `ui/quiz.js`, `validator.js` и карту XP.

## Важная граница безопасности

**Запуск Java означает выполнение произвольного Java-кода с правами пользователя, запустившего сервер.** Пять секунд, ограничение памяти/вывода, каталог `temp/`, валидация и запрет запуска при сетевом биндинге уменьшают риск случайных ошибок, но **не создают песочницу** и не могут запретить чтение файлов/сетевые операции. Используйте только свой доверенный код. Не делайте сервер публичным и не запускайте его с повышенными правами. По умолчанию он слушает **127.0.0.1**; если задать `TRAINER_HOST=0.0.0.0` для сетевого предпросмотра, эндпоинт компиляции автоматически отключается. Для чужого кода потребуется отдельная изолированная среда (VM/контейнер с отключённой сетью и ограниченными правами).

Проверка **обычных** задач сравнивает один вывод; лаборатории запускают четыре входа, но даже это не доказывает корректность для всех возможных случаев. Входы лабораторий лежат на стороне локального сервера, однако код всё равно исполняется без настоящей изоляции: для недоверенных пользователей нужен отдельный контейнер/VM. Для большого банка заданий можно заменить часовой JSON-кэш на IndexedDB; для синхронизации между устройствами потребуется отдельный защищённый сервер, аутентификация и защита данных (локальный профиль для этого не предназначен).
