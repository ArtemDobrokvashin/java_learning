## Запуск с нуля — по шагам

### 1. Установите две программы

| Программа | Как выбрать |
| --- | --- |
| [**JDK 17+ — Eclipse Temurin**](https://adoptium.net/temurin/releases/?version=21) | Рекомендуем **21 LTS**, пакет **JDK**, не JRE: нужен и `java`, и компилятор `javac`. Выберите свою ОС и архитектуру: ARM64/aarch64 для Apple Silicon, x64 для Intel/AMD 64-bit. |
| [**Python 3.10+**](https://www.python.org/downloads/) | Нужен для локального сервера. На Windows включите **Add python.exe to PATH**; в установщике JDK разрешите добавление Java в PATH, если есть такая опция. |

`PATH` — список папок, в которых система ищет программы. После установки **закройте и заново откройте терминал**, иначе он может не увидеть изменения.

<details>
<summary>Установка через пакеты на Debian / Ubuntu</summary>

```bash
sudo apt update
sudo apt install openjdk-17-jdk python3 python3-venv python3-pip
```

Проверьте версию Python на следующем шаге: в старых выпусках ОС она может быть ниже 3.10. В таком случае потребуется подходящая версия Python или обновление ОС. Эти команды не предназначены для Windows/macOS.

</details>

**Git, Node.js, Docker и Maven для занятий не нужны.** [Плагин IntelliJ IDEA](idea-plugin/README.md) — отдельное необязательное дополнение.

### 2. Проверьте версии

Откройте **Командную строку (`cmd`)** на Windows или **Терминал** на macOS/Linux. Выполните:

```text
java -version
javac -version
```

Обе команды должны работать и показывать **17 или новее**, желательно из одного установленного JDK. Затем проверьте Python:

- Windows: `python --version` (если не работает — `py -3 --version`).
- macOS/Linux: `python3 --version`.

Нужен **Python 3.10+**. Если команда не найдена или версия старее, сначала исправьте установку — [помощь ниже](#если-что-то-не-работает).

### 3. Скачайте проект и откройте нужную папку

**Без Git:** [GitHub → Code → Download ZIP](https://github.com/ArtemDobrokvashin/java_learning), затем **распакуйте** архив. Откройте внутри него папку `java-trainer`.

**С Git**, если он уже установлен:

```bash
git clone https://github.com/ArtemDobrokvashin/java_learning.git
cd java_learning/java-trainer
```

Терминал должен находиться **внутри `java-trainer`**, а не в корне репозитория и не в `frontend`:

- **Windows:** в Проводнике этой папки введите `cmd` в адресной строке и нажмите Enter.
- **macOS/Linux:** введите `cd `, перетащите папку из файлового менеджера в терминал и нажмите Enter; либо укажите её путь в кавычках после `cd`.

**Самопроверка:** `dir server.py requirements.txt` на Windows или `ls server.py requirements.txt` на macOS/Linux должны показать оба файла.

### 4. Создайте окружение и запустите сервер

Выполняйте команды **по одной**. `.venv` — отдельное окружение Python для проекта: оно не меняет системные пакеты. **Активировать его не нужно** — команды сразу вызывают нужный Python.

**Windows — Командная строка (`cmd`):**

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe server.py
```

Если работает только `py`, замените **первую строку** на `py -3 -m venv .venv`. Остальные команды те же.

**macOS / Linux — Терминал:**

```bash
python3 -m venv .venv
./.venv/bin/python -m pip install -r requirements.txt
./.venv/bin/python server.py
```

<details>
<summary>Если вместо cmd открыт Windows PowerShell</summary>

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe server.py
```

Если работает только `py`, первая команда — `py -3 -m venv .venv`. Запуск `Activate.ps1` и изменение политики выполнения скриптов **не требуются**.

</details>

Интернет нужен для установки зависимостей. После неё уроки, редактор, шрифты и проверка кода работают локально. **Не закрывайте терминал с сервером.** Сообщение Flask о development server при таком локальном запуске ожидаемо.

### 5. Откройте первый урок

Браузер обычно откроется автоматически. Если нет — перейдите на **[http://localhost:8000](http://localhost:8000)**. Именно `http`, не `https`.

Откройте первый модуль и урок. В настройках можно проверить доступность JDK; техническая проверка — [http://localhost:8000/api/health](http://localhost:8000/api/health): при исправной настройке в JSON будет `"jdkAvailable": true`.

> Не открывайте `frontend/index.html` двойным щелчком: без сервера проверка Java не работает.

**Остановить:** Ctrl+C в терминале. **Запустить в другой день:** откройте терминал в `java-trainer` и повторите только команду `… server.py` для своей ОС. Создавать `.venv` и устанавливать зависимости каждый раз не нужно.

## Если что-то не работает

Сначала прочитайте **последние строки ошибки в терминале**. Сверяйте версии Java и Python **в том же окне**, из которого запускаете сервер.

| Симптом | Решение |
| --- | --- |
| `python` не найден или открывается Microsoft Store | Попробуйте `py -3 --version`. Если Python 3.10+ найден, создайте окружение через `py -3 -m venv .venv`. Иначе установите Python с **Add python.exe to PATH** и откройте новый терминал. Если перехватывает Store — проверьте системные «Псевдонимы выполнения приложений» для `python.exe`. |
| `javac` не найден, хотя `java` работает | Вероятно, установлен только JRE или не настроен PATH. Нужен **JDK**. См. настройку Java ниже. |
| `can't open file 'server.py'` / не найден `requirements.txt` | Вы не в той папке или ZIP ещё не распакован. Вернитесь к шагу 3; оба файла должны быть видны в `java-trainer`. |
| `No module named flask` | Зависимости установлены в другой Python. Повторите установку и запуск **через `.venv`** из шага 4, а не через системный `python server.py`. |
| `No module named venv` / `ensurepip is not available` | На Debian/Ubuntu установите `python3-venv` (для отдельно установленного Python может понадобиться пакет его версии), затем повторите создание окружения. |
| `externally-managed-environment` | Вы устанавливаете пакет в системный Python. Используйте `.venv`; **не используйте `sudo pip` или `--break-system-packages`**. |
| PowerShell запрещает запуск скриптов | Не запускайте `Activate.ps1`. Вызывайте `.\.venv\Scripts\python.exe` напрямую, как на шаге 4. |
| `.venv` перестало работать после переноса папки или смены Python | Окружение не предназначено для переноса. Остановите сервер, переименуйте **только `.venv`** в `.venv-old` и повторите шаг 4. `.javada` и файлы курса не удаляйте. |
| Браузер не открывает страницу / `ERR_CONNECTION_REFUSED` | Убедитесь, что сервер не завершился с ошибкой, и откройте **http://localhost:8000**. Если `localhost` не разрешается, попробуйте **http://127.0.0.1:8000**; для сохранений это другой адрес. |
| «Нет связи с локальным сервером» при проверке | Терминал с сервером должен оставаться открытым. Запустите его снова и обновите страницу. При другом порте откройте именно адрес с этим портом. |

<details>
<summary><strong>Java установлена, но сайт не видит JDK или выбирает старую версию</strong></summary>

1. Найдите программы, которые реально запускаются: **Windows cmd** — `where java` и `where javac`; **macOS/Linux** — `command -v java` и `command -v javac`. Несколько путей на Windows могут означать несколько установок.
2. Добавьте папку **`bin` нужного JDK** в PATH раньше старых Java-путей. На Windows: найдите в поиске системы «Изменение переменных среды» → переменные пользователя → `Path`. Пример пути: `C:\Program Files\Eclipse Adoptium\jdk-21...\bin` — используйте **существующую папку своей установки**, не копируйте пример буквально. Одного `JAVA_HOME` недостаточно: сервер ищет `java` и `javac` в PATH.
3. На macOS посмотреть установленные JDK можно командой `/usr/libexec/java_home -V`. На Debian/Ubuntu при нескольких версиях проверьте выбор через `sudo update-alternatives --config java` и `sudo update-alternatives --config javac`.
4. Откройте **новый терминал**, снова проверьте обе версии и перезапустите сервер. В настройках тренажёра обновите проверку JDK.

`UnsupportedClassVersionError` обычно означает, что код скомпилирован более новым `javac`, чем запускающий его `java`. Выберите **один JDK 17+ для обеих команд**. При `Could not create the Java Virtual Machine` / `Could not reserve enough space` проверьте подходящую архитектуру JDK, закройте лишние приложения и посмотрите полный текст ошибки запуска JVM.

</details>

<details>
<summary><strong>Порт 8000 занят — Address already in use / WinError 10048</strong></summary>

Если тренажёр уже запущен в другом терминале, используйте его или остановите через Ctrl+C. Иначе выберите порт 8001:

**Windows cmd:**

```bat
set TRAINER_PORT=8001
.venv\Scripts\python.exe server.py
```

**Windows PowerShell:**

```powershell
$env:TRAINER_PORT = "8001"
.\.venv\Scripts\python.exe server.py
```

**macOS / Linux:**

```bash
TRAINER_PORT=8001 ./.venv/bin/python server.py
```

Откройте **http://localhost:8001**. Если пользуетесь плагином IDEA, укажите в нём тот же порт. Браузерные черновики по прежнему адресу сами не переносятся — см. раздел о сохранениях.

</details>

<details>
<summary><strong>Не устанавливаются пакеты: pip, SSL, прокси или доступ в сеть</strong></summary>

- Проверьте интернет и системные дату/время. Устанавливайте пакеты тем же `.venv`-Python, которым будете запускать сервер.
- При проблеме со старым pip обновите его: Windows cmd — `.venv\Scripts\python.exe -m pip install --upgrade pip`; macOS/Linux — `./.venv/bin/python -m pip install --upgrade pip`. Затем повторите установку из `requirements.txt`.
- Если `pip` отсутствует внутри окружения, попробуйте `…python -m ensurepip --upgrade`, где `…python` — путь к Python в `.venv` из предыдущего пункта. При ошибке `ensurepip` проверьте пакет `venv` / установку Python.
- На macOS после установки Python с python.org при ошибке сертификатов запустите `Install Certificates.command` из папки установленного Python в «Программах» (если этот файл есть).
- В рабочей сети SSL и скачивания может ограничивать прокси. Уточните у администратора настройки прокси и доверенного корпоративного сертификата. **Не отключайте проверку SSL ради установки.**

</details>

<details>
<summary><strong>«Запуск Java отключён в сетевом предпросмотре» или русский текст выглядит неверно</strong></summary>

Публичный предпросмотр специально не выполняет Java и не открывает личный профиль. Для занятий запустите сервер **на своём компьютере**, с настройками по умолчанию и адресом `localhost`.

Если сообщение появляется даже локально, проверьте, не заданы ли `TRAINER_HOST=0.0.0.0` или `TRAINER_DISABLE_JAVA=1`. Остановите сервер; в **Windows cmd** сбросьте их командами `set TRAINER_HOST=` и `set TRAINER_DISABLE_JAVA=`, в **macOS/Linux** — `unset TRAINER_HOST TRAINER_DISABLE_JAVA`. Затем запустите сервер заново. Не открывайте его в интернет ради обхода ограничения.

Русский вывод передаётся в UTF-8. Если вместо «Мяч» видны нечитаемые символы, обновите файлы проекта, остановите **старый процесс сервера**, запустите обновлённый `server.py` и перезагрузите страницу. Проверьте, что строка в редакторе изначально написана правильно, а Java/Javac взяты из выбранного JDK. Переключение кодовой страницы терминала само по себе не исправляет вывод в браузере.

</details>

## Как устроено обучение

**Уроки → практика → мини-экзамен → следующий модуль.** В модулях 17–22 перед практикой также есть промежуточный стоп-урок.

- В уроках: теория, образец и задания возрастающей сложности. Хард необязателен; обычные задания можно пробовать снова без ограничения попыток.
- В финальном экзамене: **5–8 заданий, зачёт от 80%**. Можно пропускать задачи и возвращаться до отправки. При успехе — **310–520 XP** один раз и достижение; при провале — **1 час на повторение**, затем пересдача. Жизни не списываются. Технический сбой JDK не запускает кулдаун.
- Java-код проверяет локальный `javac`; на выполнение программы даётся **5 секунд**. Лаборатории проверяются на нескольких входах.

## Прогресс и обновление

- **Общий профиль:** `.javada/progress.json` внутри `java-trainer`. Хранит прогресс, XP, обычные черновики, результаты экзаменов и кулдауны; используется и веб-тренажёром, и плагином IDEA.
- **Браузер:** хранит локальную копию прогресса и ответы незавершённого экзамена. После закрытия вкладки вернитесь по **тому же адресу** и нажмите «Продолжить экзамен».
- **Адрес имеет значение:** `localhost`, `127.0.0.1` и разные порты — разные хранилища браузера. Не очищайте данные сайта без необходимости: несинхронизированная работа и ответы текущего экзамена могут потеряться.
- **Перед обновлением:** остановите сервер и сделайте копию `.javada/progress.json`. Если распаковываете новый ZIP в другую папку, перенесите туда профиль в `java-trainer/.javada/progress.json` **до первого запуска**. Окружение `.venv` создайте заново по инструкции. Старую папку не удаляйте до проверки сохранений.
- При обновлении старые уроки, практика и XP сохраняются, но для дальнейшего открытия модулей потребуется сдать добавленные мини-экзамены.

Добровольные напоминания включаются в настройках: браузерные работают при открытой вкладке; для закрытого браузера можно импортировать файл `.ics` в календарь.

## Важно знать

**Это не защищённая песочница:** Java выполняется с правами вашего пользователя. Запускайте только свой или доверенный код, не используйте права администратора и не публикуйте сервер в интернете.

SQL, Spring и другие инструменты частично изучаются на моделях для стандартного JDK — реальные БД, Docker и Spring-сервер не разворачиваются автоматически. Большинство кодовых задач сравнивают ожидаемый вывод, а не доказывают корректность программы для любых данных. Тренажёр помогает начать; для профессии нужны собственные проекты, документация и обратная связь.
