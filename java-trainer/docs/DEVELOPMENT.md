# Разработчикам Javada

Это справочник по устройству проекта, API, генерации курса и тестам. Для установки с нуля и первого урока вернитесь к [пошаговой инструкции](../README.md). Все команды ниже запускаются из каталога `java-trainer/`.

## API и добавление контента

- `GET /api/health` — доступность компилятора.
- `GET /api/modules?completed=1,2&examPassed=1,2&bossPassed=17` — метаданные и статусы (`available`, `locked`, `completed`); для этого конкретного ответа учитываются параметры из текущего браузера (копия прогресса также хранится в локальном профиле). Без параметров доступен первый модуль. Все 22 модуля сейчас имеют `contentStatus: "ready"`; статус `planned` зарезервирован для возможных новых модулей без контента.
- `GET /api/ide/tasks` — локальный каталог 44 прежних задач с кодом, 99 хардов и 5 лабораторий для плагина; приватные наборы лабораторий не передаются. `GET /api/progress` возвращает состояние и черновики из `.javada/progress.json`; `POST /api/progress/merge` объединяет браузерное сохранение; `POST /api/progress/draft` обновляет черновик; `POST /api/progress/reset` с `{ "confirm": true }` сбрасывает профиль. Эти маршруты доступны **только** при локальном запуске Flask.
- `GET /data/labs.json` — условия, начальный код и один пример каждой лаборатории; другие наборы ввода браузеру не передаются.
- `GET /api/projects/task-tracker/starter` и `/api/projects/task-api/starter` — ZIP заготовок с исходниками, README, тестами и CI. Имя проекта выбирается из фиксированного списка; каталог `private/` в архив не попадает.
- `POST /api/compile` — JSON `{ "code": "public class Main { ... }", "taskType": "run", "taskId": "lab-array-report" }` (или обычный ID задания, например `m01-p06`). Режим `run` возможен только для известного серверу ID; ответы/входы из запроса клиента игнорируются. Обычная задача сверяет stdout с `expectedOutput` из JSON курса; лаборатория сверяет каждый stdout с локальными `private/lab_cases.json` (4 входа). Игнорируются разница `CRLF`/`LF` и пробелы в конце строк, но не порядок строк или пробелы внутри результата. Команда `javac` выполняется раз, затем все запуски делят 5 секунд. Режим `compile` компилирует без запуска и допускает отсутствие `taskId`. Ответ `{ "success": true|false, "kind": "ok|compile_error|wrong_output|runtime_error|timeout|...", "output": "...", "error": "..." }`. Плагин добавляет `"recordProgress": true`: после успешного выполнения сервер атомарно записывает награду/достижение и возвращает `progress`; при ошибке начислений нет. Ошибки ученика — HTTP 200, ошибки сервера — 4xx/5xx.

Чтобы изменить контент **модулей 4–22**, редактируйте авторские спецификации `tools/modules_04_08.py`–`tools/modules_19_22.py`. Цели, разборы короткого примера и типичные ошибки **всех** уроков — в `tools/lesson_notes.py`; углублённые объяснения и сценарии — в `tools/lesson_extensions.py`. Вторые пошаговые примеры, их точный вывод и связь с упражнением редактируйте в `tools/guided_lessons.py` (99 записей); **сложные вопросы и харды** — в `tools/mastery_challenges.py` (по 99 записей); подготовки к практике и подсказки для p06/p07 — в `tools/practice_guides.py` (22 записи). Если `runnable=True`, добавьте точный вывод в `RUNNABLE_OUTPUTS`; неполный фрагмент явно подпишите контекстом, не обещая самостоятельный запуск. Затем из каталога `java-trainer` выполните `python tools/generate_course.py`: он обновит теорию, добавит новые задания в модулях 1–3 **с сохранением прежних ID q1/q2**, и полностью пересоберёт модули 4–22. Потребуется лишь Python 3.10+; генерация **не нужна для обычного запуска**. Заголовки и количество уроков берутся из `frontend/data/modules.json`, а основные задания модулей 1–3 редактируются прямо в их JSON. После изменений запустите тесты.

Для новой лаборатории добавьте публичное описание в `frontend/data/labs.json` (уникальный `lab-*`, `type: code`, `mode: run`, пример, `starterCode`) и **отдельно** четыре входа/ответа в `private/lab_cases.json`; первый должен совпасть с примером. Обновите тесты и учитывайте общий лимит исполнения 5 секунд. Обе JSON-части загружаются сервером при первом обращении, поэтому после правок перезапустите Flask и сбросьте часовой кэш браузера `javada.cache.v9.labs`.

Для новых упражнений используйте типы `copy` (`sourceCode`, `language`), `choice` (`options`, `correct`, `multiple`), `fill` (`template`, `blanks`), `matching` (`pairs`), `parsons` (`lines`, `solution` с отступами 0–3), `code` (`starterCode`, `mode: "run"`, `expectedOutput`). Пропуск по умолчанию проверяет точное совпадение с `answer`; для конечного набора синонимов укажите `accepted: ["вариант1", "вариант2"]`, а если по условию допустим диапазон чисел — `validation: {"kind": "integerRange", "min": 0, "max": 120}`. Любые варианты должны быть явно отражены в условии. В `parsons` укажите только действительно равнозначные перестановки в `alternativeOrders` (массивы ID строк); отступ привязан к строке из `solution`, одинаковые закрывающие скобки взаимозаменяемы. В Python-источнике это аргумент `alternative_orders` у `P(...)`. Остальные перестановки, меняющие смысл программы, остаются ошибками. Например, в задаче про возраст принимаются и `int age = 3;`, и `int age = 25;` — пример из теории не единственный ответ. У задания обязательны уникальный `id`, `prompt`, `hint`, `explanation`. Код пишется в **публичном классе Main** без `package`; ожидаемый вывод хранится в JSON курса на сервере, а не принимается из запроса клиента. Для стоп-урока нужны пять вопросов, `boss` в `modules.json` и порог 0.8.

Метаданные и уроки кэшируются в браузере на час. Ключи кэша `javada.cache.v9.*` отделены от прогресса и черновиков `javada.state.v1` / `javada.draft.v1.*`: обновление курса сохраняет уже заработанные XP, прохождения, историю ответов и код. При загрузке старого сохранения ненужные поля жизней, таймера восстановления и компенсаций отбрасываются; пройденные уроки и модули не сбрасываются. Настройки браузерных напоминаний сохраняются рядом с прогрессом, но импортированное в календарь событие удаляется вручную. При отладке содержимого удаляйте **только кэш**, не `javada.state.v1`; после изменения источников перезапустите сервер (он кэширует индекс в памяти). Не удаляйте `.javada/progress.json` ради обновления курса: это общая копия прогресса и черновиков IDEA. Старый профиль из браузера переносится только после открытия старого origin.

Интерфейс меняется через CSS-переменные в `css/main.css`, в том числе `--green`, `--yellow`, `--red`, `--bg`, `--text`. Тёмная тема уже есть в настройках. Правила XP и повторения находятся в `js/utils/constants.js`, логика — в `gamification.js` и `review.js`. Новые типы заданий добавляйте в `ui/quiz.js`, `validator.js` и карту XP.

## Проверка

```bash
# После установки Python-зависимостей (или с .venv/bin/python):
python -m unittest discover -s tests -v

# Для DOM-тестов нужен Node.js 20+ и npm-пакеты только для разработки:
npm ci
npm test

# Плагин отдельно: JDK 17+ и сеть для первого скачивания Gradle/IDE SDK:
cd idea-plugin
./gradlew buildPlugin
```

Python-тесты проверяют API и идентичность сгенерированного курса его авторским источникам, 99 пошаговых примеров, 22 подготовки к практике, миграцию старых XP/черновиков, защиту приватного профиля и каталога IDE. Все **201** ID обычных и экзаменационных задач с кодом (44 практики, 99 хардов, 58 экзаменационных) проходят через серверный обработчик в тесте с имитацией `javac/java`: это проверка маршрутизации и серверных ключей, **не** доказательство исполнения всех решений. JS-тесты проверяют **679** исходных заданий и интерфейс экзаменов (ещё **146** заданий проверяются Python-тестами), шесть типов проверки, пропуск харда без блокировки, XP и достижения, работу интерфейса через jsdom, напоминания и сохранение. При наличии JDK ещё компилируются/запускаются **36 полных учебных примеров** и проверяется одна настоящая задача; без JDK эти проверки пропускаются. Плагин требует самостоятельной сборки на машине с JDK и доступом к Gradle/JetBrains; в данной среде его ZIP не собирался. В собственных заготовках используйте `python3 verify.py` и `mvn test`: **намеренно красные стартовые тесты** — задания ученику.

## Важная граница безопасности

**Запуск Java означает выполнение произвольного Java-кода с правами пользователя, запустившего сервер.** Пять секунд, ограничение памяти/вывода, каталог `temp/`, валидация и запрет запуска при сетевом биндинге уменьшают риск случайных ошибок, но **не создают песочницу** и не могут запретить чтение файлов/сетевые операции. Используйте только свой доверенный код. Не делайте сервер публичным и не запускайте его с повышенными правами. По умолчанию он слушает **127.0.0.1**; если задать `TRAINER_HOST=0.0.0.0` для сетевого предпросмотра, эндпоинт компиляции автоматически отключается. Для чужого кода потребуется отдельная изолированная среда (VM/контейнер с отключённой сетью и ограниченными правами).

Проверка **обычных** задач сравнивает один вывод; лаборатории запускают четыре входа, но даже это не доказывает корректность для всех возможных случаев. Входы лабораторий лежат на стороне локального сервера, однако код всё равно исполняется без настоящей изоляции: для недоверенных пользователей нужен отдельный контейнер/VM. Для большого банка заданий можно заменить часовой JSON-кэш на IndexedDB; для синхронизации между устройствами потребуется отдельный защищённый сервер, аутентификация и защита данных (локальный профиль для этого не предназначен).

## Финальные мини-экзамены (курс v9)

Во всех 22 модулях последовательность заканчивается **практикой → мини-экзаменом →
разбором результатов**. Прежние `boss` в модулях 17–22 остались промежуточными
стоп-уроками и не заменяют новый финальный экзамен. Завершённая практика сама по
себе больше не разблокирует следующий модуль: нужен также `examScores[id].passed`.
Старые уроки, практика, XP и черновики сохраняются; при обновлении старому ученику
понадобится сдать новые экзамены, чтобы продолжить последовательный маршрут.

`exam` в JSON модуля содержит `tasks`, `passingPercent: 80`, `cooldownSeconds: 3600`,
`xpBonus` (310–520 XP). В `modules.json` — краткие метаданные и `questionCount`.
Модули 1–5 содержат 5 заданий, 6–10 — 6, 11–15 — 7, 16–22 — 8. Первые два задания
лёгкие, следующие два средние, далее программы и комплексные мини-проекты.
Авторские источники: `tools/module_exams.py` (сборка и вопросы повторения) и
`tools/exam_projects.py` (условия и эталонные программы). Общий генератор сохраняет
экзамены; отдельно обновить их можно `python tools/module_exams.py`.

Локальное API:

- `GET /api/progress/exams/1` — активная попытка/последний результат, `retryAt` и
  `serverNow` в UNIX-секундах. До завершения практики — 403.
- `POST /api/progress/exams/1`, `{ "action": "start" }` — создать или восстановить
  попытку. До окончания кулдауна возвращает предыдущий неуспешный результат.
- `POST /api/progress/exams/1`, `{ "action": "submit", "attemptId": "...",
  "answers": { "task-id": "answer" } }` — проверить весь экзамен. Форматы ответов:
  choice — массив ID; fill — объект ID пропуска → строка; matching — ID слева → ID
  справа; parsons — массив `{id, indent}`; code — строка Java-кода. Пропуски неверны.
- `/api/modules` дополнительно принимает `examPassed=1,2`. Этот публичный маршрут
  лишь строит карту по параметрам браузера; удостоверение сдачи и награда создаются
  только локальным сервером, не этим запросом.

`exams.py` проверяет не-код на сервере, Java передаёт общему `judge_java` из
`server.py`. Порог считается **без округления**: `correct * 100 >= 80 * total`
(требуется 4/5, 5/6, 6/7, 7/8). При провале кулдаун определяется серверными часами;
жизни и награды за отдельные задания не затрагиваются. Сбой JDK, занятый компилятор
или таймаут компилятора оставляют попытку открытой. Повторная отправка завершённой
попытки возвращает прежний результат без повторного XP.

`progress.json` атомарно хранит отдельный верхнеуровневый блок `exams` (попытки,
результаты, кулдауны), `state.examScores`, награду `xpLedger["exam:1"]` и достижение
`exam:m01`. Слияние старых браузерных/IDE-сохранений не стирает этот блок и не может
установить сдачу экзамена. Это локальный однопользовательский тренажёр, **не система
защиты от списывания**: JSON с ответами публичный, владелец ПК управляет файлами и
часами. В сетевом предпросмотре экзаменационное API, профиль и запуск Java выключены.

Интерфейс использует `#/exam/1`, хранит ответы всех типов, текущую задачу и ID
попытки в `javada.exam.v1.1`. Код редактора сохраняется также при `pagehide`, не
дожидаясь debounce. До отправки доступны номера задач, «Пропустить» и возврат.
При закрытии вкладки можно нажать «Продолжить экзамен» и восстановить ответы.
Результат и кулдаун восстанавливаются с сервера; сброс профиля удаляет и экзамены.
Кэш курса `javada.cache.v9.*` не затрагивает прогресс `javada.state.v1`.

### UTF-8 на всём пути

`Main.java` записывается с `encoding="utf-8"`, компилятор получает `-encoding UTF-8`.
Проба JDK и основная проверка используют общие `JVM_UTF8_OPTIONS` / `JAVAC_UTF8_OPTIONS`:
`file.encoding`, `sun.stdout.encoding`, `sun.stderr.encoding` (JDK 17), а также
`stdout.encoding` / `stderr.encoding` (новые JDK). Для javac эти параметры передаются
через `-J`. Это важно на Windows: одной `file.encoding` недостаточно для потоков.
Дочерний процесс получает чистое окружение с `LANG` / `LC_ALL=C.UTF-8`, без
унаследованных `JAVA_TOOL_OPTIONS`; stdout/stderr читаются как байты и явно
декодируются UTF-8 с `errors="replace"`. Некорректный байт не обрушает сервер.

Проверки: `python -m unittest discover -s tests -p 'test_*.py'` и `npm test`.
`tests/test_exams.py` содержит дополнительные интеграционные тесты с реальным JDK:
русский stdout и диагностика компилятора, плюс все 58 эталонных программ экзаменов.
Эти проверки автоматически пропускаются, если `java`/`javac` отсутствуют в PATH;
на Windows их следует запускать с JDK 17 и актуальным JDK для проверки потоков ОС.
