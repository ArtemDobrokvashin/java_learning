# Портфолио 2 · Task API (Spring Boot + JPA + H2)

**Продолжение Task Tracker:** веб-API для задач. Это **отдельный необязательный проект**, а не задание встроенного компилятора. Нужны JDK 17+, Maven 3.9+ и интернет при первом скачивании зависимостей. Для запуска самого тренажёра Maven/Spring не требуются.

## Запуск

```bash
mvn test                  # один интеграционный тест пока красный — это ваша задача
mvn spring-boot:run       # слушает localhost:8080
curl -i -X POST http://localhost:8080/api/tasks -H 'Content-Type: application/json' -d '{"title":"Написать тест"}'
curl -i http://localhost:8080/api/tasks
```

Внутри уже есть простая вертикаль: `POST /api/tasks` возвращает `201` с ID и данными, `GET /api/tasks` — список, `GET /api/tasks/{id}` — запись или `404`; пустое название — `400`. База H2 в файле `tasks-db.mv.db` рядом с проектом, чтобы задачи переживали перезапуск (для **локальной разработки**, не для продакшена). Тесты работают с отдельной H2 в памяти, не трогая ваши данные.

## Техническое задание и критерии готовности

1. Добавьте `PATCH /api/tasks/{id}/done`: существующая задача становится выполненной, ответ `200` с обновлёнными данными; неизвестный ID → `404`. Тест `markAsDoneAndPersist` специально падает, пока это не реализовано. Добавьте тест повторного вызова.
2. Добавьте `DELETE /api/tasks/{id}` → `204`, при отсутствии → `404`. Напишите интеграционный тест на оба случая.
3. Вынесите бизнес-правила из контроллера в сервис. Отделите HTTP DTO от JPA-сущности: не возвращайте Entity напрямую. Проверьте `@Valid` для пустого и слишком длинного названия; документируйте ошибки.
4. Убедитесь, что данные переживают перезапуск приложения. Для CI проверьте `mvn test`; конфигурация тестовой БД изолирована от рабочей. Для собственного развития замените H2 на PostgreSQL и опишите миграцию схемы (Flyway/Liquibase), но не считайте это частью простого офлайн-запуска тренажёра.
5. В своём репозитории добавьте README с таблицей методов/статусов и примером `curl`, диаграммой Controller → Service → Repository → DB, скриншотом/логом тестов, ограничениями и инструкцией запуска. Сделайте серию осмысленных коммитов и опишите, **почему** выбрали такие статусы и структуру.

**Проверяемые навыки:** HTTP-контракт, валидация, Spring MVC, DI, JPA, интеграционные тесты, работа с БД, документация и CI. Заготовка и зелёные тесты — свидетельство практики, но не гарантия готовности к работе: отдельно нужно уверенно отвечать на вопросы, читать чужой код и разбирать реальные требования.
