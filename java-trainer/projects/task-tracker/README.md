# Портфолио 1 · Task Tracker CLI (Java 17, без зависимостей)

**Задача:** сделать небольшое, но надёжное приложение управления задачами. Это проект, который можно положить в GitHub и объяснить на собеседовании: инкапсуляция, коллекции, файлы, ошибки, автоматические проверки и документация. Заготовка намеренно **не решает** основные методы: сначала `verify.py` должен быть красным.

## Запуск и проверка

Понадобятся Python 3.10+ и JDK 17+ в PATH; Maven не нужен.

```bash
python3 verify.py                        # сперва упадёт — это нормально
mkdir -p out
javac -encoding UTF-8 -d out src/*.java
java -cp out Main --data tasks.tsv
# вводите команды, завершите словом exit
python3 verify.py                        # после реализации тесты должны пройти
```

На Windows можно использовать `py verify.py`, затем создать `out` командой `mkdir out`, скомпилировать `javac -encoding UTF-8 -d out src\Main.java src\Task.java src\TaskService.java src\TaskRepository.java` и запустить `java -cp out Main --data tasks.tsv`. Тесты используют временный каталог и не трогают ваши данные.

## Контракт ввода/вывода

| Команда | Ответ |
| --- | --- |
| `add Купить молоко` | `ADDED 1` (следующий ID = максимальный ранее выданный + 1) |
| `done 1` | `DONE 1` |
| `done 99` | `ERROR not_found` |
| повторное `done 1` | `ERROR already_done` |
| `add` или `add   ` | `ERROR empty_title` |
| `list` | по одной строке `id|todo|название` или `id|done|название` в порядке ID; если нет задач — `EMPTY` |
| неизвестная команда/нечисловой ID | `ERROR invalid_command` |
| `exit` | `BYE` |

Заголовок задачи допускает пробелы и кириллицу; после `trim()` он не может быть пустым. Для простого формата хранения запретите в названии символы `|`, табуляцию и перевод строки (выберите и опишите сообщение об ошибке). Файл `tasks.tsv` в UTF-8: `id<TAB>done<TAB>title` по одной строке на задачу. Сохраняйте после успешного `add` и `done`, не меняйте файл при ошибке. Повторный запуск с тем же `--data` обязан сохранять ID и статусы. Не храните сгенерированные данные и файлы `.class` в Git.

## План работы

1. **Зелёный список:** реализуйте чтение пустого и существующего файла в `TaskRepository.load()`. Вручную испытайте несколько строк; решите, как реагировать на повреждённый файл, и документируйте выбор.
2. **Правила предметной области:** в `TaskService` реализуйте `add`, `complete`, сортировку списка; не изменяйте состояние при неуспехе. Используйте максимальный ID, а не длину списка.
3. **Надёжное сохранение:** записывайте сначала временный файл, затем заменяйте основной; для систем, где атомарное перемещение не поддержано, предусмотрите понятное поведение. Проверьте кириллицу.
4. **Проверки:** добейтесь прохождения `python3 verify.py`, добавьте минимум две свои проверки (например, старый ID после перезапуска и повреждённая строка).
5. **Портфолио:** в своём README покажите установку, примеры команд и вывода, архитектуру `Main → Service → Repository`, принятые ограничения, тесты и скриншот терминала. Создайте свой Git-репозиторий, сделайте коммиты по этапам и убедитесь, что workflow зелёный.

**Важно:** даже зелёный `verify.py` проверяет только перечисленные случаи, а не доказывает качество любой реализации. На собеседовании будьте готовы объяснить решения, ошибки, разделение ролей и обработку данных, а не только показать значок CI.
